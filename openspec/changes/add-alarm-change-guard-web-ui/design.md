## Context

见 `proposal.md`。`agent-web` 当前是 Spring MVC 可执行模块，只提供 REST API，没有前端构建链或静态 UI。HuaweiCloudAlarmChangeGuard 是独立服务，已经暴露创建、审批、屏蔽、恢复、重试、详情和审计 API，并由 JWT 角色保护。DPOMAgent 的既有边界禁止自动生产写操作和持有华为云凭据。

## Goals / Non-Goals

**Goals:**

- 在不引入 Node/SPA 框架的前提下提供清晰、快速、可测试的浅色系操作页面。
- 让高风险动作始终由用户显式发起，并在屏蔽前展示不可忽略的精确范围确认。
- 保持 Change Guard 为唯一写控制面和审计事实源，DPOMAgent 仅承担静态资源托管。
- 支持桌面和窄屏、键盘操作、可感知异步反馈与常见错误恢复。

**Non-Goals:**

- 不在 DPOMAgent 中实现审批逻辑、状态机或云 Provider；只允许固定目标和 operations 路径的透明同源转发。
- 页面不实现登录、会话或凭据输入，不接收 Bearer Token、AK 或 SK。
- 不改变 HuaweiCloudAlarmChangeGuard API 契约，不操作遗留 APM 2.0 私有接口。
- 不引入 React/Vue、Node 构建链、数据库迁移或额外基础设施。

## Decisions

### 1. 使用原生 HTML、CSS 和 ES Module

页面放在 `agent-web/src/main/resources/static/change-guard/`，由 Spring Boot 原生静态资源处理器托管。HTML 保持语义化，CSS 使用设计 token 和响应式 grid，JavaScript 按 `api-client`、`state`、`render` 与入口模块拆分。

选择原生模块是因为当前仓库没有前端工具链，页面规模有限，浏览器原生能力足以覆盖表单、表格、对话框和请求状态。相比引入 SPA 框架，它减少供应链、构建和部署复杂度；若后续界面显著扩大，可在保持 API client 契约的前提下替换渲染层。

### 2. 浏览器通过固定同源入口调用 Change Guard

部署提供不含秘密的 `config.js`，只声明 DPOMAgent 同源转发基础路径。页面不允许临时改写目标地址，所有 `fetch` 请求通过同一个 API client 构造，路径必须为相对的 `/api/v1/operations...`。转发端的下游地址由服务端配置固定，且只转发 operations 路径；页面不收集凭据。

该转发不解释业务响应、不保存请求或凭据，也不产生第二份审计事实；它只解决浏览器同源和本地网络限制，Change Guard 仍是唯一写控制面。

### 3. 页面不提供登录或会话

页面不呈现连接状态、会话按钮或 Token 输入框，API client 不保存凭据且不构造 Authorization 请求头。错误渲染只使用后端脱敏字段，不拼接请求头或原始异常对象。需要认证的环境应在页面之外完成统一认证或由同源部署边界处理。

### 4. 单一操作工作区和显式状态机

页面分为变更表单、冻结清单、生命周期动作、规则结果和审计时间线。客户端只缓存当前操作详情，并以服务端状态决定按钮：屏蔽仅对 `APPROVED` 开放；恢复对服务端定义的可恢复状态开放；重试仅对恢复失败状态开放。每次写响应后都以返回详情覆盖本地状态，不自行推断成功。

屏蔽使用原生 `<dialog>` 或等价可访问对话框，列出操作 ID、项目/区域、按来源统计、恢复截止时间并要求输入变更单号确认。恢复按钮始终使用高可见度主动作样式，避免危险状态下被次要操作淹没。

### 5. 浅色视觉系统与渐进式表格

以近白背景、蓝灰文本、低饱和蓝为主色，成功/警告/危险使用浅底色和深色文字，所有状态同时带文本或图标。桌面采用双栏工作区；小于约 860px 时改为单栏，规则表格转为带字段标签的卡片行。字体使用系统字体，不加载外部字体或图标资源。

### 6. 测试分层

- Java/MockMvc 验证页面和静态资源可访问、界面无登录/会话/凭据输入、生产和开发 profile 均不新增写控制器。
- 对 JavaScript 纯函数与 API client 采用浏览器可执行的轻量测试页或无框架模块测试，验证 URL 约束、无 Authorization 请求头、幂等键和状态到动作映射。
- 使用可控 Change Guard HTTP stub 做人工或自动浏览器验收，覆盖成功流程、预检失败、补偿/部分恢复和窄屏布局。
- 全量 Maven 验证继续证明 DPOMAgent 原诊断能力无回归。

## Risks / Trade-offs

- [跨源 CORS 配置错误导致页面不可用] → 部署文档给出精确源站配置和启动前连通性检查，页面区分网络、CORS、认证与业务错误。
- [浏览器页面遭 XSS 后操作被篡改] → 不使用动态 HTML 注入，所有远端文本通过 `textContent` 渲染；不加载第三方脚本，配置严格 CSP。
- [API 契约变化导致按钮或字段错误] → API client 集中映射并以 OpenAPI/HTTP stub 契约测试覆盖关键字段；未知状态默认禁用写动作。
- [用户误屏蔽错误范围] → 只展示并使用后端冻结清单，屏蔽前二次确认操作 ID、范围、变更单和恢复截止时间。
- [刷新导致当前页面状态丢失] → 操作可通过输入操作 ID恢复查询。

## Migration Plan

1. 在开发 profile 部署静态页面和空 API 配置，验证默认不产生外部请求。
2. 指向预生产 Change Guard，配置精确 CORS/CSP，完成 HTTP stub 和隔离项目验收。
3. 生产部署先保持导航入口隐藏；确认角色、恢复手册和外部逾期监控后再启用入口。
4. 回滚时移除或隐藏静态入口并清空 `config.js`；Change Guard 独立服务和所有恢复能力不受影响。
